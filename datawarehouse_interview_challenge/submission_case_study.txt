This Kafka message is an event-tracking message used for analytics, capturing user interactions or system events within Lalamove app. The payload contains detailed metadata about the user, device, network, application, and event-specific details in order to track user behavior, monitor app performance and user experience and support analytics for business insights, such as user demographics, geographic trends, or feature usage.
The message is triggered by a specific user action or system event in the app, such as deliver location when user selecting a point of interest (b_poi_select), update a location (onLocationChanged), as indicated by arg3 and the event is captured by an SDK (e.g., sdkVer: guapp-1.0.1.39) integrated into the app, which logs the event and sends it to Kafka.
The app’s SDK collects the event data and sends it to a Kafka producer. Then, the producer publishes the message to a Kafka topic (user_events or location_events). Lastly, Kafka brokers store the message in the topic’s partitions, where it can be consumed by downstream systems (analytics pipelines, data warehouses) for processing.

4.	I selected PostgreSQL which is a popular, open-source relational database.
String Processing: Store the Kafka message as a JSONB column, which allows efficient querying and indexing. For frequently queried fields, extract them into separate columns for faster access. Use PostgreSQL’s full-text search on JSONB data for advanced querying.
JSONB: 
•	Pros: Flexible schema, no need to predefined columns, supports complex queries, efficient with GIN indexes.
•	Cons: Slower for simple queries compared to normalized columns, larger storage due to JSONB overhead.
Extracted Columns: 
•	Pros: Faster queries for common fields, simpler SQL, better for reporting.
•	Cons: Less flexible, requires schema updates if new fields are added.
Full-Text Search: 
•	Pros: Powerful for searching across all JSON fields, good for ad-hoc analysis.
•	Cons: Not ideal for structured queries, higher CPU usage for indexing.

Database Schema:
CREATE TABLE standardized_events (
  event_id String,
  session_id String,
  trigger_time DateTime,
  user_type String,
  aaid String,
  os String,
  os_version String,
  country String,
  city String,
  app_version String,
  event_name String,
  event_category String,
  event_status String,
  event_properties JSON,
  context JSON
)
ENGINE = MergeTree()
PARTITION BY toDate(trigger_time)
ORDER BY (trigger_time, country);
